# Deploy Lao Rice API + Web to Ubuntu 24 VPS

Same pattern as **lao-edu-api** / **lao-edu-web**: push to `main` → GitHub Actions SSH → `deploy/deploy.sh`.

| App | Path on VPS | Port | GitHub repo |
|-----|-------------|------|-------------|
| API | `/opt/lao-rice-api` | **8081** | `maisyltnv/lao-rice-api` |
| Web | `/opt/lao-rice-web` | **3000** | `maisyltnv/lao-rice-web` |

Run everything as user **`deploy`** (not `root`).

If **lao-edu** is on the same VPS, use different ports for rice web (e.g. `PORT=3001`) and set `NEXT_PUBLIC_API_URL` to the public API URL.

---

## Part 1 — Create `deploy` user (as root, once)

```bash
adduser deploy
usermod -aG sudo deploy
usermod -aG docker deploy

mkdir -p /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
# Paste your Mac/laptop public key (for you to SSH in):
nano /home/deploy/.ssh/authorized_keys
chmod 600 /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh

# Allow deploy to run vps-setup (needs apt/systemd once)
echo 'deploy ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/deploy
chmod 440 /etc/sudoers.d/deploy
```

From your Mac:

```bash
ssh deploy@YOUR_VPS_IP
```

---

## Part 2 — GitHub deploy keys (on VPS as `deploy`)

**API key:**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/github_lao_rice -N ""
cat ~/.ssh/github_lao_rice.pub
```

Add at: https://github.com/maisyltnv/lao-rice-api/settings/keys → **Deploy key** (read-only).

**Web key:**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/github_lao_rice_web -N ""
cat ~/.ssh/github_lao_rice_web.pub
```

Add at: https://github.com/maisyltnv/lao-rice-web/settings/keys → **Deploy key**.

Test:

```bash
GIT_SSH_COMMAND='ssh -i ~/.ssh/github_lao_rice -o StrictHostKeyChecking=accept-new' \
  git ls-remote git@github.com:maisyltnv/lao-rice-api.git HEAD
```

## Part 3 — First-time API setup

Merge/push `deploy/` folder to `main`, then on VPS:

```bash
sudo bash -c 'curl -fsSL https://raw.githubusercontent.com/maisyltnv/lao-rice-api/main/deploy/vps-setup.sh | bash'
```

Or clone first:

```bash
export GIT_SSH_COMMAND="ssh -i $HOME/.ssh/github_lao_rice -o StrictHostKeyChecking=accept-new"
sudo mkdir -p /opt && sudo chown deploy:deploy /opt
git clone -b main git@github.com:maisyltnv/lao-rice-api.git /opt/lao-rice-api
cd /opt/lao-rice-api
sudo ./deploy/vps-setup.sh
```

(`vps-setup.sh` uses `sudo` for apt/systemd; GitHub key is read from `/home/deploy/.ssh/`.)

Create admin (once):

```bash
curl -X POST http://127.0.0.1:8081/auth/admin/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"CHANGE_ME_STRONG"}'
```

## Part 4 — First-time Web setup

Replace `YOUR_VPS_IP` with your server IP:

```bash
export NEXT_PUBLIC_API_URL=http://YOUR_VPS_IP:8081
export PORT=3000
export GIT_SSH_COMMAND="ssh -i $HOME/.ssh/github_lao_rice_web -o StrictHostKeyChecking=accept-new"
git clone -b main git@github.com:maisyltnv/lao-rice-web.git /opt/lao-rice-web
cd /opt/lao-rice-web
sudo -E env NEXT_PUBLIC_API_URL="$NEXT_PUBLIC_API_URL" PORT="$PORT" ./deploy/vps-setup.sh
```

Use your **public VPS IP** in `NEXT_PUBLIC_API_URL` (not `127.0.0.1`) so browsers can call the API.

## Part 5 — GitHub Actions secrets (both repos)

In **lao-rice-api** and **lao-rice-web** → Settings → Secrets → Actions:

| Secret | Example |
|--------|---------|
| `VPS_HOST` | `62.171.159.75` |
| `VPS_USER` | `deploy` |
| `VPS_SSH_KEY` | Private key that can SSH as `deploy` (generate on Mac: `ssh-keygen -t ed25519 -f ~/.ssh/vps_deploy -N ""`, put `vps_deploy.pub` in `/home/deploy/.ssh/authorized_keys`) |

After `git push origin main`, Actions runs `/opt/lao-rice-api/deploy/deploy.sh` or `/opt/lao-rice-web/deploy/deploy.sh`.

## Part 6 — Security (fresh VPS after malware)

```bash
sudo apt update && sudo apt upgrade -y
sudo ufw allow OpenSSH
sudo ufw allow 8081/tcp
sudo ufw allow 3000/tcp
sudo ufw enable
sudo apt install -y fail2ban
```

- Change SSH from password-only to keys: `/etc/ssh/sshd_config` → `PasswordAuthentication no`
- Do **not** expose Postgres `5433` publicly (only localhost)
- Use strong `JWT_SECRET` (auto-generated by `vps-setup.sh`)
- After first admin, block `/auth/admin/register` at firewall or remove route in production
